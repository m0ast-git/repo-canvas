# Пять вопросов за две минуты

Это протокол проверки полезности, а не заявление об уже проведённом исследовании пользователей.

## Проверка с владельцем

Выберите 3–5 внешних репозиториев разных типов и их владельцев, которые знают фактическое поведение. Зафиксируйте версию Repo Canvas, commit проекта, размер карты, стоимость построения и дату. Не отправляйте чужой закрытый код модели без разрешения.

Откройте только готовую карту. За две минуты попросите ответить:

1. Что делает продукт и какой результат получает пользователь?
2. Как выбранный сценарий доходит от начала до результата?
3. Зачем выбранный модуль и с кем он связан?
4. Что сейчас находится в работе и что действительно подтверждено?
5. Что изменилось с указанного прошлого состояния?

Запишите время каждого ответа и конкретные ошибки. Владелец сверяет ответы с реальным продуктом: 0 — неверно/выдумано, 1 — частично полезно, 2 — достаточно и верно. Честный ответ «нет данных» допустим, если сведений действительно нет. Сохраняйте исходные ответы и замечания вместе с версией; сравнивайте одинаковые вопросы и репозиторий до/после изменения.

## Автоматическая проверка

```sh
repo-canvas evaluate --root /path/to/project --max-tokens 80000
repo-canvas evaluate --root /path/to/project --baseline cp-EXISTING-ID --max-tokens 80000
```

Команда явно запускает до трёх модельных вызовов. Проверяющий получает исходные фрагменты, читатель — только карту, затем проверяющий сопоставляет пять ответов. Модельные инструменты выключены. Перед каждым вызовом проверяется оценка остатка бюджета; фактическое потребление может отличаться от оценки. Без baseline вопрос об изменениях должен признать отсутствие исходного состояния.

Результаты сохраняются по уникальному ID в `.repo-canvas/evaluations/`, вместе с версией пакета, ревизией карты, вопросами, ответами, оценками, временем и расходом. `latest.json` используется страницей «Состояние». У каждого результата `humanValidation: false`: модель не заменяет проверку реальным человеком. Пять разных ID ответов обязательны, пропущенные/повторные ответы не дают успешную оценку.

`npm run test:review` проверяет протокол на изолированной фикстуре с искусственными ответами и без платных вызовов. Оценка 10/10 в этой фикстуре проверяет сохранение результата; она ничего не доказывает о понятности реальной карты.
