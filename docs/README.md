Требование описывает нужное поведение; отчёт подтверждает только конкретную версию и проверенный сценарий. При противоречии с кодом не объявляй автоматически неверным требование: установи, что изменилось, и проверь последние решения владельца. Старый успешный тест не подтверждает новую сборку.

Последние явные указания владельца имеют приоритет. Каждый вид требований поддерживается в одном документе из таблицы; изменения вносятся туда, а не в очередной параллельный план. Источники реализации — код и проверки. `output/` содержит локальные доказательства, не инструкции; исторические изображения `design-system/references/` показывают прежние концепты, не действующую спецификацию.
