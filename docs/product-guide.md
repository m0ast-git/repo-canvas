# Repo Canvas: использование

Карта помогает вернуться от отдельной доработки к устройству проекта: зачем он существует, какие части дают результат, как между ними проходят данные и что меняется сейчас.

## Первый запуск

Нужны Node.js 22+ и Git. Первая структура и сохранённая карта работают без модели; смысловые объяснения требуют авторизованного Codex, Claude Code либо Kimi Code. При работе из этого checkout:

```sh
npm ci
npm run build
node repo-canvas/scripts/canvas.mjs init
node repo-canvas/scripts/canvas.mjs skeleton
npm start
```

Вместо `codex` можно выбрать `claude` или `kimi`. Проверка подключения доступна в «Настройки» в верхней навигации. Авторизация выполняется штатным CLI выбранного провайдера; Canvas использует уже настроенный доступ.

Открытие страницы загружает сохранённую карту. Построение запускается явно через действие обновления карты; в пустом проекте доступно первое построение. Сервер остаётся в текущем терминале и открывает локальный адрес. Для другого порта: `node repo-canvas/scripts/canvas.mjs start --port 4280`.

## Работа с картой

- Пустое поле перемещает камеру. Карточка или заголовок перемещает объект вместе с вложенными частями. Ручка выбранной области меняет её размер. При вытаскивании исходная рамка неподвижна; принимающая область расширяется при вставке. Объект можно оставить вне областей.
- «Переименовать» в панели элемента меняет название и описание; также работает двойной клик. Ctrl/Cmd+Z отменяет своё действие; чужая правка того же объекта защищена от автоматического отката.
- Ctrl/Cmd+F ищет элемент, область или работу. «Вся карта» возвращает сводки областей и связи между ними. Приближение открывает исходные модули; на узком экране области перелистываются стрелками. Полные данные остаются в поиске и панели.
- Верхняя навигация открывает карту, сценарии, решения, состояние и настройки. Контекст раскрывает назначение и вопросы; выбранный элемент показывает входы, выходы, критерии и источники.
- Выберите сценарий: текущий шаг показывает два модуля, действие и условие. «Далее», «Назад» и стрелки клавиатуры меняют шаг. «Весь сценарий» открывает последовательность. Нажатие на модуль возвращает к общей карте; Escape закрывает просмотр.
- «Уточнить смысл» открывает поправку обычной фразой. «Короче», «Подробнее» и «Объясни через пример» запускают готовую просьбу одним нажатием. Можно объяснить короче, привести пример, добавить недостающую часть, объединить элементы, отметить план, отменить решение или убрать неверную связь. Поправка имеет отдельную отмену.
- «Скопировать контекст» готовит краткую справку для нового диалога. Если буфер обмена недоступен, сохраняется текстовый файл.

## История

История открывается главами: работа агента, правки владельца за день, построение, решение или коммит. Внутри главы и в режиме «Все отметки» доступны исходные номера и ID. Нижний ползунок и стрелки выбирают состояние с заданным шагом. Автопроигрывания нет.

При новом посещении «Пока вас не было» сравнивает последнюю просмотренную отметку с состоянием на входе. Изменённые модули отмечены; кнопка «Понятно» сохраняет новую границу.

В раскрытой истории доступны фильтры коммитов, сессий, решений и собственных отметок; поиск по дате, номеру и названию; сравнение от выбранного состояния до другого состояния или Live. Комментарий к прошлому хранится отдельно и не исправляет прошлый снимок.

Просмотр прошлого не останавливает наблюдение. Live продолжает обновляться; кнопка возвращает к актуальной карте. Требование к истории — сохранять старые подписи, решения, положение и размеры и использовать записанную геометрию без нового построения. Граница проверки после последних изменений маршрутизатора указана в [состоянии реализации](implementation-status.md).

Если карта в тот момент не записывалась, показывается пробел. По выбранному Git-коммиту можно отдельно запустить ограниченную реконструкцию. Она использует старые исходники без переключения рабочей ветки. Дата коммита и дата нынешней реконструкции различаются; современная раскладка не объявляется оригинальным видом прошлого. Повторное открытие готовой реконструкции не вызывает модель.

## Построение и язык

Локальный сборщик читает код и относящиеся к проекту публичные диалоги. Историк выделяет намерения, принятые и отменённые решения и привычный язык владельца. Собственные сообщения пользователя имеют приоритет; цитата, вставленный код или слова агента не доказывают уровень знаний пользователя.

Архитектор собирает ответственности и направленные сценарии. Проверка ссылок и иерархии выполняется кодом, фактов — отдельной моделью по исходным фрагментам. Другая роль проверяет понятность. Неподтверждённый фактами кандидат не заменяет рабочую карту. Версию, прошедшую сверку фактов, можно сохранить с пометкой о незавершённой проверке понятности и продолжить позже.

Модель выбирается по роли и доступному разрешённому каталогу, без закреплённых названий. В настройках можно назначить конкретную модель отдельной роли. Архитектор, историк, проверяющий, редактор и наблюдатель выполняют разные задачи; смена одного провайдера не требует аккаунта другого.

Ограничиваются число вызовов и оценка токенов на построение. Фактическое потребление законченного вызова может отличаться от оценки; после исчерпания ориентира новые вызовы не запускаются. Кандидат, знания, готовые проверки и незакрытые замечания сохраняются для продолжения. Цены неизвестного провайдера не предполагаются.

Профиль объяснения хранится локально. Явное пожелание владельца имеет приоритет и используется в будущих пояснениях. Исторические формулировки остаются прежними. Смысловая поправка проверяется по источникам; изменение изложения отдельно проверяется на сохранение смысла.

При включённом наблюдении файлы связываются с модулями без модели, одно резюме подводит итог хода. Конец сессии сверяется с кодом, собственные сообщения пополняют решения и профиль. В свободное время историк дочитывает их порциями в пределах фоновой квоты. Изменения вне сессии замечает файловый наблюдатель; одинаковые экспорты не доказывают неизменность поведения. Заявление «готово» не подтверждает реализацию или тесты.

В «Состоянии» видны расход всех ролей, ошибки, паузы, логический объём данных и Git. Лимиты редактируются в настройках. Временная пауза на этом запуске сервера обозначается отдельно и снимается явным действием владельца.

## Хранение и доступ

Сервер слушает только loopback. Открытие его страницы создаёт локальную HttpOnly/SameSite-сессию. API проверяет Host, Origin и токен; случайный токен хранится в игнорируемом каталоге проекта.

`.repo-canvas/events.jsonl` — исходный журнал. Текущий снимок, индекс истории и промежуточные снимки ускоряют чтение; потерянные вычисляемые кеши можно восстановить из журнала. Координаты готовых чекпоинтов, комментарии, поправки, архивы использованных фрагментов и реконструкции хранятся рядом. Для переноса или резервной копии сохраняйте **весь `.repo-canvas`**, а не только журнал.

Формат событий остаётся v1. Промежуточные статусы и точные дубли работы не создают чекпоинт; её начало и конец создают. Новые производные снимки сжимаются gzip, прежние JSON читаются совместимо. `compact-cache` сначала показывает расчёт; `--apply` сжимает только производные снимки после проверки обратимости. Исходный журнал и историческая геометрия сохраняются. `repair --apply` предварительно сохраняет оригинал повреждённого журнала. История не удаляется автоматически ради уменьшения размера.

[Подключение MCP и хуков](agent-connections.md) выполняется явно, без автоматической правки личных настроек. [Протокол пяти вопросов](evaluation.md) отделяет реальную проверку владельцем от автоматической оценки по версиям.

Выбранные фрагменты кода и диалогов отправляются выбранному исполнителю. Секретные файлы, скрытые рассуждения и посторонние проекты исключаются. Чтение диалогов можно отключить: новые сообщения не читаются, прямое открытие отключённого источника блокируется. Уже сохранённые выводы и формулировки остаются частью карты и могут входить в контекст вопросов; это не команда удаления ранее полученного знания. Архивирование старого фрагмента сохраняет основание старого вывода, включая незакоммиченный код.

Модель получает подготовленные данные в отдельной временной среде с отключёнными инструментами. Команды из исходников и диалогов не выполняются. Построение не запускает тесты проекта и не объявляет их выполненными. Временные модельные процессы останавливаются вместе с сервером.

## Границы проверки совместимости

Ниже результаты прежних проверок, а не текущая проверка доступности установленных CLI. Дата и незакрытая приёмка — в [состоянии реализации](implementation-status.md).

| Исполнитель | Протокол | Реальная проверка в этой реализации |
| --- | --- | --- |
| Codex | Структурированный вывод, изолированные вызовы, продолжение сессии | Подключение и построение проверялись реальными вызовами |
| Kimi Code | Независимый CLI, агент без инструментов, разбор stream-json | Дошёл до провайдера; проверка остановилась на upstream HTTP 500 |
| Claude Code | Независимый CLI, запрет инструментов/MCP, JSON Schema | Адаптер и ошибки проверены автоматически; CLI отсутствовал на проверочной машине |

Интерактивные проверки выполнены в Windows/Chrome. CI настроен также для macOS и Linux; работа на физическом слабом ноутбуке и Mac требует отдельного замера. Подробные результаты: [implementation-status.md](implementation-status.md).
