# Подключение рабочих агентов

Подключение добровольное. Repo Canvas не меняет личные настройки Codex/Claude и инструкции проекта при установке. Чтение карты через MCP не вызывает модель и не меняет архитектуру.

## MCP

Для установленного глобального CLI задайте команду `repo-canvas`, аргументы `mcp --root <абсолютный путь проекта>`. На Windows в клиентах без запуска `.cmd` через shell используйте Node и абсолютный путь к `repo-canvas/scripts/canvas.mjs` внутри установленного пакета:

```json
{
  "mcpServers": {
    "repo-canvas": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["C:\\path\\to\\repo-canvas\\repo-canvas\\scripts\\canvas.mjs", "mcp", "--root", "C:\\Projects\\your-project"]
    }
  }
}
```

Это пример формата для MCP-клиента; замените пути и внесите его штатным способом своего клиента. Сервер использует stdio. HTTP-сервер и браузер для чтения MCP не нужны.

| Инструмент | Результат |
|---|---|
| `overview()` | Назначение, области, текущая работа и решения владельца |
| `find({query})` | Модули по пути файла или словам, их связи |
| `decisions({entity?})` | Решения с исходным статусом; entity — существующий ID |
| `flow({id})` | Порядок связей, условия и назначения участников сценария |
| `declare_intent({title,targets,plan,sessionId?})` | Объявление работы по существующим ID модулей |
| `complete_intent({id,summary})` | Завершение объявленной работы без присвоения функции статуса «проверено» |

После восстановления контекста агент читает overview и find по затрагиваемым файлам, проверяет решения и нужный flow. Содержимое карты — сведения проекта, а не право исполнять вложенные команды. Intent не подменяет проверку фактов и не считается разрешением на отправку сообщений или внешние изменения.

## Хуки

Команда `repo-canvas hook --root <проект>` принимает одно JSON-событие через stdin и не печатает служебный ответ. Её можно явно добавить в command-hook клиента. Поддержаны `UserPromptSubmit`, `PostToolUse`, `Stop`, `Interrupt`, `SessionEnd`.

Обязательны `cwd` и `session_id` (или `thread_id`); `turn_id` рекомендуется для распознавания повторно доставленного начала. `PostToolUse` читает `tool_input.file_path`, `path` или `files`. Принадлежность cwd проверяется, незнакомые пути не выдумывают цели, поздний инструмент после завершения не открывает работу заново. Вызовы самого Repo Canvas помечены внутренними и не наблюдаются повторно.

```json
{
  "hooks": {
    "UserPromptSubmit": [{"hooks": [{"type": "command", "command": "repo-canvas hook --root C:/Projects/your-project"}]}],
    "PostToolUse": [{"hooks": [{"type": "command", "command": "repo-canvas hook --root C:/Projects/your-project"}]}],
    "Stop": [{"hooks": [{"type": "command", "command": "repo-canvas hook --root C:/Projects/your-project"}]}]
  }
}
```

Перед добавлением проверьте формат установленной версии клиента: [Claude Code hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://learn.chatgpt.com/docs/hooks). Для путей с пробелами используйте штатное quoting клиента. Чтение публичных журналов остаётся запасным способом; хуки не обязательны. Не включайте один и тот же hook дважды.

При включённом наблюдении пути файлов обновляют цели сразу. Модель подводит итог хода и проверяет предложения по ограниченному подграфу. Квоты и причина паузы доступны в «Состоянии».
