# Сквозные критерии приёмки

Это требования и проверочные сценарии, а не утверждение, что они все пройдены на нынешней версии. Последние результаты и открытые проверки находятся в [состоянии реализации](implementation-status.md). Выбирай набор по области влияния из [системной сводки](system-map.md), не запускай дорогие проверки из-за несвязанной правки.

## Карта и взаимодействие

- Первое движение после нажатия не теряется. Предпросмотр и результат переноса совпадают; ориентир расхождения — не более 1 CSS px. Перенос поддерева, смена области/родителя, свободное положение, resize, undo/redo и перезагрузка согласованы.
- Внутреннее перемещение не перепаковывает соседей. При извлечении исходный контейнер неподвижен; при вставке принимающий вмещает узел. Отмена восстанавливает координаты, размеры, членство и прежнее отсутствие owner-полей; чужая конкурентная правка того же объекта не откатывается молча.
- Положение, сохранённое в другой вкладке, появляется в Live без ручного обновления. Камера и выбранное прошлое не скачут вслед за фоновыми данными.
- Одновременно соблюдаются: единый стиль линий, связь стрелок с концами, отсутствие длинных совпадающих участков, обход карточек и заголовков, совпадение видимой линии с выбором мышью. Проверяется окончательная SVG-геометрия, а не только промежуточные точки.
- Hover устойчив и снимается при уходе; клик закрепляет объект/связь; подписи не перекрывают содержимое и не залипают при pan/drag/resize. Выносные указатели остаются внутри канваса.
- Во время камеры маршруты неизменны и новый поиск путей не запускается. Во время drag узел следует мыши без ожидания тяжёлого расчёта. Устаревший ответ worker не применяется.
- Контур области и исходящая связь используют один цвет; нейтральные источники серые, обмен сохраняет оба исходных цвета. Планы имеют пунктир, смешанная область остаётся сплошной. Свежая active-работа выделяет цели/предков и пульсирует на общем/близком виде; blocked/planned/завершённая/устаревшая работа не пульсирует. Проверяются смена реализации без перепрокладки, завершение без фантомов, история и reduced motion.
- Общий вид, выбранный сценарий, объект с поправкой и история проверяются в обеих темах, рабочем/общем масштабе и узком окне. География и идентичность узлов сохраняются; детали не заменяют карту списком или пустыми прямоугольниками.
- Клавиатура, видимый фокус, Escape/возврат фокуса, доступное редактирование помимо двойного клика, названия и статусы не зависят только от цвета. Ориентиры контраста: 4.5:1 обычный текст, 3:1 крупный текст и значимые элементы. Сенсорные цели и интервалы проверяются в фактическом UI.

## Построение, знания и язык

- Обзор читается на первом экране; переход к модулю сохраняет географию. Мобильный обзор допускает перелистывание областей. Текущий шаг виден полностью, порядок и условие соответствуют направленным отношениям.
- Упорядочивание сохраняет закреплённые x/y. Отмена возвращает прежнее отсутствие закрепления, включая отсутствие x/y у автоматического элемента.

- Контрольные случаи: выдуманный символ, существующий файл с неверным описанием, разрыв/неверное направление сценария, устаревшее основание, конфликт плана с кодом. Существования файла недостаточно для подтверждения поведения.
- Диалоговый набор содержит принятое решение, позднюю отмену, непринятое предложение агента, цитату/код, противоречие, форк с копией истории, старый путь рабочего дерева и чужой проект. Принадлежность не определяется одним именем папки; сомнение не приводит к молчаливому импорту.
- Собственные слова владельца определяют профиль объяснения; явное пожелание сильнее предположения модели. Смена изложения сохраняет факты, участников, условия, направления и степень подтверждения. Единичная реплика или цитата не переименовывает весь проект.
- Источник сохраняет автора, время события/извлечения, версию, конкретный фрагмент и адрес сообщения/файла. Решение можно открыть у источника; неизвестные мотивы не выдумываются. Удалённый файл не подменяет историческое основание современным содержимым.
- Повторный импорт не удваивает знания и чекпоинты. Новый хвост анализируется без повторной отправки всей неизменной истории. Охват, пропуски, дубли и неопределённость видимы; при противоречии дочитывается оригинал.
- Достаточные источники позволяют строить карту без обязательной анкеты. Критичный для смысла пробел вызывает точечное уточнение. Некритичная неизвестность не мешает полезному результату.
- Кандидат проходит схему, основания и понятность до атомарного применения. Адресное замечание и языковая поправка не запускают ненужное полное построение. Контекст незатронутых соседей и уже проверенные источники сохраняются, их изменение проверяется по версиям/хешам.
- Переименование выполняется без модели; смысловая поправка относится к выбранному объекту и имеет отмену. Ручные имена, решения, свободное положение и родитель переживают новую генерацию; исторические подписи не переписываются.
- Реальный пользователь должен восстановить смысл знакомого проекта, пройти один сценарий и объяснить роль модуля. Модельный вердикт о понятности не заменяет эту проверку.

## Исполнители, наблюдение и ошибки

- Чтение журналов и вызов моделей — разные адаптеры. Каждый заявленный исполнитель проверяется без обязательного аккаунта другого: доступ → структурированный ответ → построение → поправка → повторная проверка. Mock-тест не доказывает реальный доступ.
- «Авто» соблюдает разрешённый пул, роли и лимит; выбор одной роли не меняет остальные молча. Недоступность, невалидный JSON, таймаут, отмена, возобновление и исчерпание лимита имеют определённый исход. Цены и поддержка неизвестных возможностей не выдумываются.
- Успех, ошибка, прерывание и потеря связи различимы. Время завершённого запуска не растёт; суммируются известные вызовы, пропущенные метаданные отмечаются. Сырые ответы проверяющей модели не становятся уведомлениями; сообщения проходят через `client/src/job-message.js`.
- Ожидание модели не останавливает чтение других журналов и работу UI. Сохраняются события, пришедшие во время запроса; поздний ответ не открывает завершённую работу заново. Проверить таймаут дочернего процесса при продолжающем работать сервере.
- Предложенные критерии исходного плана: новое событие доступной сессии видно за ≤2 s при искусственном ожидании модели 10 s; потеря сервера обозначается за ≤5 s. Эти числа требуют отдельного замера.
- Команды из кода/диалогов не исполняются. Изоляция, разрешённые источники, отключение диалогов и ограничения провайдера проверяются отдельно от наличия неинтерактивного CLI. Отключение чтения не обещает удаления уже сохранённого знания.

## История и данные

- 1000 тиков завершённой задачи не создают повторные вызовы/записи. Пустой финальный ответ снимает ожидание проверки; квоты атомарны и переживают рестарт. Хуки отклоняют чужой cwd, позднее событие не воскрешает завершённую работу.
- MCP чтение не пишет карту; intent меняет только активность. Первый скелет не вызывает модель и явно обозначает границы доказательства. Пять модельных ответов не заменяют проверку владельцем.
- SSE передаёт изменения двум вкладкам; в простое исправный поток исключает HTTP-опрос состояния. Отключение сервера включает fallback и предупреждение.

- Выбранный чекпоинт, номер, подписи, состав, отношения, состояния, иерархия и геометрия соответствуют одной ревизии. Live имеет отдельный указатель. Историческая активность вычисляется относительно времени снимка.
- Ползунок, шаг 1/заданный шаг, диапазон по времени/числу, края, точный переход, поиск/фильтры и возврат Live проверяются на длинной истории. Охват шкалы не меняет шаг автоматически. При быстрой протяжке отменяются устаревшие запросы; состояние и подпись меняются согласованно. Клавиши таймлайна не перехватывают ввод текста и жесты карты.
- Сравнение указывает обе границы и их вид: коммит, сессия, чекпоинт, Live. Ветки не превращаются в выдуманную единую историю. Коммит без изменений карты остаётся понятным состоянием.
- Одно принятое действие записывается атомарно; промежуточные движения мыши не создают чекпоинты. Повторы, одинаковые даты, поздний импорт и параллельная запись не теряют/не удваивают события. Чужая актуальная блокировка записи не удаляется как устаревшая.
- Снимок «готовится» не выдаётся за готовый. Поздняя геометрия другой ревизии не перезаписывает checkpoint. Новое подтверждение/поправка создаёт запись, а не переносит готовность назад во времени.
- Просмотр сохранённой истории не вызывает модель, не пишет карту и не меняет рабочую ветку. Реконструкция использует старые исходники без checkout; время события и время реконструкции различаются, отсутствие оснований/геометрии обозначается явно.
- Журнал v1 читается совместимо. Перед миграцией/repair есть резервная копия и путь восстановления. Для переноса сохраняется весь `.repo-canvas/`; история не удаляется скрыто ради экономии места.

## Нагрузка и доставка

На большом графе обзор показывает агрегаты, а подробный вид — до 60 маршрутов выбранного фокуса. Это не требование одновременно показывать все 600 связей. Готовность обзора и выбранного фокуса измеряется отдельно.

Обновление проверяет целостность и подписанное происхождение до установки. Отсутствующий gh, неподтверждённые workflow/ref и неподписанный архив приводят к отказу и восстановлению прежнего runtime. Default init не меняет package.json и настройки агента.

Проверочные наборы исходного плана: 30 объектов/60 связей; основной 250/600 с вложенностью до 4 и 6 работами; нагрузочный 1000/2500 с длинными RU/EN-названиями и 20 работами. История — 10 000+ чекпоинтов/100 000+ событий; диалоги — форки, повторы и поздние отмены. Это профили проверки, не ограничения продукта. Реальная карта дополняет синтетику.

Ниже сохранены **предложенные целевые бюджеты**, не подтверждённые показатели текущей сборки:

| Метрика | Цель |
|---|---|
| Полезное открытие основной сохранённой карты | ≤2 s, UI доступен во время фоновых расчётов |
| Поиск, выбор, панель | p95 ≤100 ms |
| Pan/zoom/drag основного набора | Ориентир 60 FPS, p95 интервала ≤20 ms, без повторных зависаний ≥100 ms |
| Pan/zoom нагрузочного набора | Ориентир ≥30 FPS, без потери данных |
| Простой UI + сервер | ≤1% CPU машины за минуту, модельные процессы отдельно |
| Память основного набора | Вкладка с workers ≤300 MB, сервер ≤150 MB; без устойчивого роста после 100 действий |
| Основной JS | ≤200 KB gzip; тяжёлые расчётные модули отдельно |
| История с готовым индексом | Соседний шаг p95 ≤100 ms; произвольный переход p95 ≤300 ms |

Замер указывает CPU/RAM, ОС, браузер, окно, масштаб и набор. Обычный ноутбук: 4 ядра, 8 GB, встроенная графика, SSD, 1366×768; замедление CPU не подменяет физическую машину. Проверить desktop и узкие окна, системный масштаб 100/125/150%, обе темы; при доступности Mac/Safari. Локальные FPS и задержка не объявляются полевым INP; ориентир INP ≤200 ms p75 требует собственных наблюдений.

При оптимизации сначала исключаются лишние обновления/повторное чтение, используются worker, ограниченные кеши, видимые объекты и готовые сессии. Кеш исторических состояний ограничен; seek не читает журнал с начала. Открытие панели/истории не должно создавать утечки обработчиков, WASM-сессий или дочерних процессов.

Проверка поставки: сборка → npm-пакет → установка в новый проект → настройка → карта → работа → перезапуск → обновление/откат. Проверить старые/неполные данные, повреждённый журнал, смену ветки и отказ модели/сервера. Только разрешённый изолированный прогон с заранее определёнными исполнителями и расходом; пользовательское хранилище не служит тестовой фикстурой. Поддержка Windows/macOS/Linux разделяет CI и реальную интерактивную приёмку. Собственные временные процессы и файлы убираются после проверки.
