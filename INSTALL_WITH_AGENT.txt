REPO CANVAS — УСТАНОВКА В СУЩЕСТВУЮЩИЙ ПРОЕКТ

Твоя задача: установить Repo Canvas в текущий репозиторий, построить смысловую карту, запустить локальный сервер и вернуть владельцу рабочую ссылку.

Границы работы:
- сохрани пользовательские и чужие изменения;
- не меняй продуктовый код;
- не добавляй инструкции, skills или hooks рабочим агентам;
- не устанавливай системные компоненты без разрешения владельца.

1. Из корня проекта прочитай его инструкции и проверь `git status`.

2. Проверь Node.js 22+, npm и Git. Если компонента не хватает, сообщи владельцу его точное название и остановись.

3. Выбери один источник установки.

   Если владелец дал ссылку на GitHub:

   npm install --save-dev --save-exact --ignore-scripts github:m0ast-git/repo-canvas#v0.10.0

   Если в корне проекта лежит `repo-canvas-0.10.0.tgz`:

   npm install --save-dev --save-exact --ignore-scripts ./repo-canvas-0.10.0.tgz

   Затем выполни:

   npx --no-install repo-canvas setup

   `setup` проверит локальное подключение Codex, запустит read-only Architect на `gpt-5.6-sol` с reasoning medium, построит смысловую карту, проверит её понятность независимым читателем и включит Observer на `gpt-5.4-mini`. Observer будет следить за публичными локальными журналами Codex, Claude Code и Kimi Code, относящимися к этому репозиторию.

   Установщик добавляет пакетные scripts, ignored-каталог `.repo-canvas/` и необходимые строки `.gitignore`. Если `package.json` отсутствовал, npm создаст минимальный служебный manifest. Не запускай `npm init` и не придумывай метаданные проекта. При конфликте остановись, ничего не перетирая.

4. Запусти один foreground-сервер в устойчивом терминале:

   npm run repo-canvas:start

   Если сервер Repo Canvas для этого проекта уже работает, используй его. Не завершай посторонние процессы. Если порт 4173 занят, выбери свободный:

   npm run repo-canvas -- start --port <port>

5. Дождись строки `Repo Canvas listening at ...`: сервер сам откроет карту в браузере. Если браузер не открылся, открой напечатанный локальный адрес — вкладка подключится автоматически. Проверь фактическое отображение:
   - вся иерархия проекта существует на карте постоянно и не перестраивается при масштабе;
   - при отдалении активность подсвечивает область, затем затронутый элемент, а вблизи — конкретный процесс агента;
   - области, сущности и подписи связей читаемы;
   - если продукт предполагает человека, он показан круглым участником вне областей, а его связь объясняет конкретное действие, ввод, решение, ожидание или результат;
   - связи не перекрывают карточки;
   - страница не имеет горизонтального скролла;
   - активная и черновая работа хорошо заметна;
   - фон двигает камеру, заголовок области переносит её вместе с содержимым, а карточка переносит ноду и её вложенность;
   - двойной клик по области или ноде редактирует название и описание, а двойной клик по связи — её подпись;
   - переключатель темы работает, а статус `онлайн` отцентрирован в шапке.
   - во время Architect-прохода постоянная плашка показывает этап, heartbeat и время; после завершения она показывает применённый результат либо точную ошибку.

6. Выполни:

   npm run repo-canvas -- check
   npm run repo-canvas -- observer status

7. Верни владельцу:
   - локальную ссылку;
   - число областей, сущностей и связей;
   - результат `check`;
   - единственный реальный блокер, если он остался.

После этой установки терминал для будущих обновлений не нужен. Когда выйдет новый проверенный релиз, внизу Canvas появится кнопка `Update`; она установит новую версию в ignored-каталог, перезапустит сервер и сохранит текущую карту.

После запуска сервера Observer создаёт черновую карточку при первом событии новой работы и затем уточняет её по публичным событиям сессии. Обычным рабочим агентам Canvas-инструкции не нужны. Claude `thinking`, Kimi `think`, tool results и скрытый reasoning игнорируются. Во время наблюдения Observer не сканирует файлы проекта заново.

После крупной перестройки проекта или по запросу владельца обнови смысловую карту:

   npm run repo-canvas -- architect --refresh

Остановить наблюдение:

   npm run repo-canvas -- observer disable

Включить его снова:

   npm run repo-canvas -- observer enable
